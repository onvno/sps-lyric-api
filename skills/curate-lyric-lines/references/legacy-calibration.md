## 数据依据

用户早期亲手挑选的旧 SQL 数据包含 701 条已批准摘句，来自 240 首歌曲。分析应读取 `legacy_backup_sps` 与 `legacy_backup_apply` 对应的 `lyric_segments.text`，不要从公开条目中已经被空格压平的文本反推换行。

- 693/701 是多行段落。
- 630/701 是 2–4 行，约占 90%。
- 平均正文约 25.6 个字符；20–39 字是最大区间。
- 8 条历史单行记录属于人工例外，不作为自动选句模板。
- 超过 4 行的历史记录说明完整语义有时需要更长上下文；自动阶段仍限制 2–4 行，必要时由人工 `hold` 后扩展。

## 人工选择呈现出的模式

旧摘选不是孤立金句集合，常见价值来自句间结构：

1. 先给具体场景，再落到时间、关系、选择或自我认识。
2. 先陈述愿望或常态，再用“但、却、如果、原来”等形成张力。
3. 连续提问不是为了押韵，而是把人物困境逐层展开。
4. 并列、复沓和对照在最后一行形成新的意义，而不是重复副歌。
5. 自然意象只有与记忆、命运、成长、孤独或归属发生关系时才有价值。
6. 可品味的段落往往同时包含具体语言和未完全说尽的余地。

## 对自动流程的约束

- 从完整歌词中生成相邻 2–4 行窗口，使用 `\n` 保存原始换行。
- 不跨空行、段落标签、制作信息或其他边界拼接。
- 默认预筛阈值 76，每首最多 3 段。
- 同歌候选不能共享任何完全相同的歌词行；重复副歌只保留一个代表段落。
- 预分只近似“值得终审”的可能性。最终仍按思想余味、完整性和句间推进人工评分。
- 已批准的旧 SQL 摘选是校准集，不参与候选重建，也不受每首 3 段上限影响。
