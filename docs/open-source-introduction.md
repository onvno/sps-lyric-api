# 我做了一个收藏歌词的小网站，现在开源了

听歌的时候，总会碰到几句特别喜欢的歌词。

有时随手记在备忘录里，有时截个图。时间一长，想再找出来，就得翻半天。记得歌词却想不起歌名的情况，也不少见。

所以我做了「摘句」：一个可以搜索、整理歌词，也能把歌词做成图片的小网站。现在把代码放到了 GitHub，感兴趣的朋友可以下载，搭一个自己的歌词收藏站。

仓库地址：[github.com/onvno/sps-lyric-api](https://github.com/onvno/sps-lyric-api)

## 打开以后，能做些什么

首页就是歌词卡片。可以直接往下看，也可以输入歌词、歌名或创作者来搜索。想按歌曲找，就切换到“按歌曲浏览”，展开一首歌，里面是它收录的摘句。

![网站首页](screenshots/01-home.jpg)

列表可以翻页，也能筛选中文或英文。搜索会查找整个已发布曲库，不只查当前这一页。

第一次启动，网站会自动放入 **20 条演示摘句**，方便先试试。截图用的也是这份演示数据。之后可以慢慢添加自己的收藏。

## 喜欢哪一句，就把它做成图片

点开卡片，可以看到歌词、歌名、创作者和来源。下面有一个“分享图片”入口。

目前做了三种模板：暖纸、松林、深夜。选好喜欢的样式，看一下预览，就能下载 PNG 图片。

![选择模板并下载歌词图片](screenshots/02-share.jpg)

图片宽度是 1080 像素，歌名和创作者也会一起带上。歌词较长时，图片会跟着变长，不会只截取前面几行。

有些旧中文歌词是用空格隔开每一句的，做成图片时会自动换行。英文单词之间的空格会保留。

图片直接在浏览器里生成，不需要另找截图工具，也不用把歌词传到其他图片服务。

## 自己添加歌词，也有地方管理

平时打开网站，只能浏览。想添加内容，需要先打开管理员模式，设置一个自己的管理口令。

![管理员录入页面](screenshots/03-admin.jpg)

添加歌词有两种方式：

- 已经挑好了几行：去“录入”，填上歌词、歌名、演唱者等信息，提交后就会显示在网站上。
- 手头是完整歌词：去“审核”，上传歌词，或者从支持的来源导入。网站先整理出一些候选片段，再由你决定保留哪些。

管理页面也能搜索和翻页。某首歌找不到时，可以把“有待审候选”切换成“全部来源歌曲”；已经处理过的片段，也能查看状态。

目前还没有做完整的已发布歌词编辑、下架页面。这部分以后再补。歌词的来源、署名和使用条件，也需要自己核对，不能只靠程序判断。

## 怎么在自己的电脑上跑起来

有 Node.js 22.5 或更新版本的话，打开终端，执行：

```bash
git clone https://github.com/onvno/sps-lyric-api.git
cd sps-lyric-api
npm ci
npm start
```

然后在浏览器打开 `http://localhost:8787`，就可以用了。不用先下载歌词库，也不用另外安装数据库服务。

网站用 SQLite 保存数据，说白了就是把内容存在本机的一个数据库文件里。

如果平时用 Docker，也可以这样启动。下面的命令适用于 macOS、Linux，Windows 用户可以在 WSL 中执行：

```bash
git clone https://github.com/onvno/sps-lyric-api.git
cd sps-lyric-api
cp .env.example .env
mkdir -p data dist/releases
printf 'LOCAL_UID=%s\nLOCAL_GID=%s\n' "$(id -u)" "$(id -g)" >> .env
docker compose up -d --build --wait
```

这种方式不用在电脑上另装 Node.js，访问地址还是 `http://localhost:8787`。如果这个端口已经被其他程序占用，可以改 `.env` 文件里的 `PORT`。

想看看有没有正常启动，可以打开 `/api/health`。下面是这次 Docker 部署后的实际返回，`ok: true` 表示检查通过：

![Docker 部署后的状态检查](screenshots/04-health.jpg)

这里显示有 20 条演示摘句，管理员模式没有开启。截图用的是单独的测试端口，所以和默认的 8787 不一样。

开启管理模式的方法和常用操作，放在了 [管理员手册](../ADMIN.md) 里。

## 收藏的数据，怎么保管

自己的歌词库放在 `data/` 目录里。用 Docker 时，它也保存在电脑上，不会因为重新创建容器就被清空。更新网站代码，也不会自动替换你的收藏。

不过，重要的内容还是要备份。项目提供了两个命令，用途不一样：

- `npm run db:backup -- --version 2026.10.30`：备份自己的完整数据库，留给自己保存。
- `npm run db:release -- --version 2026.10.30`：只打包仓库自带的演示数据，方便给别人试用，不会读取你的私人歌词库。

如果以后要安装别人提供的数据库，要注意：这是用新库替换旧库，不会自动把两边的收藏合在一起。安装前会备份，也有恢复方法，具体步骤在 [部署说明](deployment.md) 里。

## 最后说明两件事

这次开源的是网站代码，采用 MIT License。歌词和其他第三方内容，仍然要看各自的来源和使用条件；代码可以用，不代表所有歌词也都能随意传播。仓库里的演示摘句附有来源说明，详见 [内容使用说明](../NOTICE.md)。

另外，虽然仓库名叫 sps-lyric-api，这次主要是让大家自己搭建和使用。网页背后有读取数据的接口，但暂时不提供一个让其他应用长期调用的公共 API 服务。

如果你也想整理自己的歌词收藏，欢迎下载试试。遇到安装、换行或图片下载问题，可以在 GitHub Issues 里说一下你用的系统、浏览器，以及是怎么遇到问题的。想建议收录某首歌，也有单独的模板可以填写。
